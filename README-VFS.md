# Віртуальна файлова система ЄPython

Цей документ описує, як у ЄPython влаштована віртуальна файлова система (далі — VFS), як з нею працювати через **Розпорядник файлів**, бічну панель файлів проєкту та з Python-програм, зокрема через `tkinter` і `easygui`.

> Коротко: VFS — це емуляція файлової системи у `localStorage` браузера. Вона поводиться як звичайне дерево тек і файлів (`/`, `/data/a.txt`, `.`/`..`), але фізично файли лежать не на диску комп’ютера, а у сховищі сайту в браузері.

## Загальний принцип

Код ЄPython виконується у пісочниці браузера, тому він **не має прямого доступу до реального диска**. Це фундаментальне обмеження браузерів: сайт не може довільно читати чи записувати файли користувача. Натомість ЄPython надає власну віртуальну ФС, яка емулює поведінку справжньої:

```python
with open('/notes.txt', 'w') as f:
    f.write('Привіт!')

with open('/notes.txt', 'r') as f:
    print(f.read())
```

Ті самі файли бачать:

| Компонент | Що робить |
|---|---|
| `lib/jsfs.js` | ядро VFS: `window.FileSystem`, дерево тек і вміст файлів у `localStorage` |
| Розпорядник файлів (`lib/filedialog.js`) | графічний менеджер віртуальних файлів |
| Бічна панель файлів проєкту (`index.html`, `lib/lib.js`) | список файлів відкритого проєкту |
| `lib/customfile.js` | реалізація Python `open()` поверх VFS |
| `lib/skulpt/os/__init__.js` | `os`, `os.path` поверх тієї самої VFS |
| `lib/skulpt/shutil.py`, `tempfile.py` | операції з файлами та тимчасові файли |
| `lib/skulpt/_tkinter.js`, `lib/tk/tk-engine.js` | підключення VFS до Tk-діалогів |
| `lib/skulpt/easygui/easygui.py` | зручні обгортки над Tk-діалогами |

Основний екземпляр VFS створюється під час запуску IDE:

```js
window.fsToBrowse = new FileSystem('epythonfs');
```

Модуль `os` використовує `Sk.__jsfs = new FileSystem('epythonfs')`. Оскільки назва однакова (`epythonfs`), обидва екземпляри працюють із **одними даними**, але мають **власний поточний каталог** (`cwd`).

## Де зберігаються дані

Сховищем є **`localStorage` браузера**, а не IndexedDB і не реальний диск.

| Ключ `localStorage` | Призначення |
|---|---|
| `epythonfs_filesystem` | об’єкт-дерево каталогів і файлів у JSON |
| `epythonfs_file_0`, `epythonfs_file_1`, … | вміст окремих файлів |

Важливі наслідки:

- дані прив’язані до **походження сторінки** (протокол, домен, порт). Відкриття через `http://127.0.0.1:8000` і `http://localhost:8000` — це різні сховища;
- очищення даних сайту (cookies/site data) або використання іншого браузера/профілю призводить до втрати VFS;
- обсяг обмежений квотою `localStorage` браузера. Для важливих файлів використовуйте **«Зберегти файл»** у Розпоряднику або **💾 «Зберегти проєкт»** у бічній панелі;
- у консолі браузера переглянути ключі можна так:

```js
Object.keys(localStorage).filter(k => k.indexOf('epythonfs_') === 0)
```

## Шляхи й поточний каталог

- Корінь VFS — `/`.
- Розділювач — `/` (як у POSIX).
- Підтримуються `.` і `..`.
- Абсолютні шляхи типу `/notes.txt`, `/data/result.csv` є найнадійнішими.
- Відносні шляхи обчислюються відносно `cwd` **конкретного екземпляра `FileSystem`**.

Практичне правило:

- Розпорядник файлів щоразу під час відкриття скидає свій `cwd` до `/`.
- `os.getcwd()` / `os.chdir()` змінюють каталог екземпляра, який використовує модуль `os`.
- `open()` і Tk-діалоги працюють через `fsToBrowse` / `engine.hooks.fs`.

Тому після `os.chdir('/data')` не варто очікувати, що всі інші інструменти автоматично змінять свій каталог. У програм краще використовувати абсолютні шляхи або явно передавати `initialdir` у діалогах.

## Розпорядник файлів

### Як відкрити

На панелі керування натисніть **«Файли»**, а потім у відкритому вікні виберіть **«Розпорядник файлів»**.

### Навігація

- Файлова система починається з кореня `/` («Верхній рівень»).
- Одинарний клік — виділити елемент.
- Подвійний клік по теці — увійти в неї.
- Подвійний клік по файлу — відкрити попередній перегляд.
- **⬆ На рівень вище** — перейти до батьківської теки.
- Ланцюжок адрес над списком (breadcrumbs) — швидкий перехід до потрібної теки.

### Дії

| Кнопка | Дія |
|---|---|
| 📁➕ **Створити теку** | створює теку в поточному каталозі |
| 📤 **Додати файл** | завантажує файл із комп’ютера до VFS |
| 👁 **Переглянути файл** | показує текст або зображення |
| 📋 **Копіювати** | копіює виділений файл у буфер |
| ✂️ **Вирізати** | готує файл до переміщення |
| 📥 **Вставити** | вставляє файл у поточну теку |
| ⬇️ **Зберегти файл** | завантажує файл на комп’ютер звичайним браузерним завантаженням |
| 🗑 **Видалити** | видаляє файл або теку з підтвердженням |

Обмеження завантаження з комп’ютера:

- дозволені лише `.txt`, `.csv`, `.png`;
- `.txt` і `.csv` зберігаються як текст;
- `.png` зберігається у вигляді Data URL (`data:image/png;base64,...`), тому його можна переглядати безпосередньо в менеджері та використовувати в `PIL`/`pygame`;
- копіювати/вирізати можна лише **файли**, не цілі теки;
- видалення незворотне: кошика й скасування дії в менеджері немає;
- перейменування в самому Розпоряднику не передбачене — змінюйте ім’я через бічну панель або `os.rename()`.

## Бічна панель файлів проєкту

Кнопка з іконкою **📁/📂** розташована над редактором поруч із назвою поточного файла (у коді — `#btn_toggle_file_sidebar`, заголовок **«Файли проєкту»**). Клік показує або ховає панель і оновлює розміри редактора.

Панель відображає два списки:

1. **Файли редактора** — `PythonIDE.files`. Головний файл збережено внутрішньо як `mycode.py`, але в інтерфейсі він показується як `<назва_проєкту>.py`.
2. **Ресурси проєкту** — `PythonIDE.projectAssets`, наприклад `.png`. Такі елементи позначаються 🖼️ і відкриваються переглядом, а не в текстовому редакторі.

Кнопки в шапці панелі:

| Кнопка | Дія |
|---|---|
| ✚ **Створити новий файл** | створює `newfile.txt`, далі `newfile2.txt`, `newfile3.txt` … і відкриває його в редакторі |
| 📤 **Додати до проєкту** | додає один або кілька файлів `.py`, `.txt`, `.json`, `.csv`, `.png` |
| 💾 **Зберегти проєкт** | пакує файли проєкту в архів `.yepp` і завантажує його |
| 📂 **Відкрити проєкт** | відкриває архів `.yepp` |

Для елемента списку є меню ⚙️:

- **Переглянути** — для файлів-ресурсів (наприклад, PNG);
- **Перейменувати**;
- **Видалити файл**.

Правила перейменування:

- ім’я має відповідати шаблону `^[A-Za-z0-9_.]+$` — лише латинські літери, цифри, крапка й підкреслення;
- ім’я не має збігатися з уже наявним;
- файл `.png` обов’язково має зберегти розширення `.png`.

### Чим панель відрізняється від Розпорядника

Це **різні подання**:

- Розпорядник показує реальне дерево VFS у `localStorage`.
- Бічна панель показує список файлів відкритого проєкту (`PythonIDE.files` + `projectAssets`).

Додавання, перейменування й видалення з бічної панелі намагаються синхронізувати VFS. Проте файл, доданий лише через Розпорядник, не обов’язково одразу з’явиться у списку проєкту, а файл, щойно створений у панелі, може існувати спочатку лише у вкладці редактора — поки не буде записаний. Для Python-коду це зазвичай не проблема: `open()` має окремий пріоритет пошуку (див. нижче).

Архів `.yepp` — це ZIP з файлами проєкту. Під час відкриття шлях усередині архіву не відтворюється: використовується лише назва файлу, тому **структура тек втрачається**.

## Робота з файлами з Python

### `open()`

`open()` у ЄPython працює через `lib/customfile.js`. Підтримуються звичні режими `r`, `w`, `a` та їхні варіанти з `b`, контекстний менеджер, `read()`, `write()`, `readline()`, `readlines()`, `seek()`, `tell()` і ітерація за рядками.

Пріоритет пошуку під час читання:

1. `PythonIDE.files[<ім’я>]` — відкриті вкладки/модулі IDE;
2. прихований DOM-елемент з ідентифікатором, що дорівнює імені файла;
3. VFS (`fsToBrowse`, тобто `localStorage`).

Під час запису:

- дані пишуться у VFS;
- через хук `Sk.filewrite` оновлюється список файлів IDE, якщо шлях не починається з `/tmp/`;
- тимчасові файли `/tmp/...` у списку проєкту не з’являються.

Параметри `encoding`, `errors`, `newline`, `closefd` і `opener` у поточній реалізації фактично ігноруються: текст зберігається як рядок JavaScript. Бінарні режими існують, але дані зберігаються у вигляді рядка (bytes перетворюються у latin-1), тому для зображень краще використовувати PNG/Data URL та відповідні бібліотеки, а не сирі `bytes`.

### `os` та `os.path`

Модуль реалізовано у `lib/skulpt/os/__init__.js` поверх `Sk.__jsfs`.

Доступні, зокрема:

```text
os.getcwd(), os.chdir()
os.listdir(), os.mkdir(), os.makedirs()
os.rmdir(), os.removedirs()
os.remove(), os.unlink()
os.rename(), os.replace()
os.stat(), os.lstat()
os.walk(), os.scandir()
os.path.join/split/splitext/basename/dirname
os.path.abspath/normpath/realpath
os.path.exists/isfile/isdir/isabs/getsize/commonpath
os.getenv/putenv, os.urandom
```

Застереження:

- `os.stat()` повертає розмір і тип, але час створення/зміни завжди `0`;
- `os.replace()` — фактично той самий `os.rename()`;
- `os.path.expanduser()` відсутній, не покладайтеся на `~`;
- функції `os` реалізовані як native JS і не приймають keyword-аргументів: використовуйте `os.makedirs('/data', 0o777, True)` замість `exist_ok=True`;
- символьних посилань і реальних прав доступу немає.

### `shutil`

`lib/skulpt/shutil.py` підтримує `copy`, `copy2`, `copyfile`, `copytree`, `move`, `rmtree`, `which`, `get_terminal_size` та `disk_usage`.

`shutil.disk_usage()` повертає нулі — VFS не має реального обмеження обсягу всередині себе (обмеження накладає лише квота `localStorage`). `shutil.make_archive()` не реалізований і викидає `NotImplementedError`.

### `tempfile`

`lib/skulpt/tempfile.py` створює тимчасові файли у віртуальній теці `/tmp`. Доступні `NamedTemporaryFile`, `TemporaryFile`, `SpooledTemporaryFile`, `mkstemp`, `mkdtemp`, `mktemp`, `gettempdir`.

Такі файли живуть у VFS, але не потрапляють до бічної панелі проєкту. Для `NamedTemporaryFile` типово `delete=True`, тобто файл видаляється після `close()`.

### Інші бібліотеки

- **PIL**, **pygame**, **pgzrun**, **turtle** можуть читати ресурси з тієї самої VFS. PNG, додані через Розпорядник або панель проєкту, доступні за віртуальним шляхом.
- **numpy** зберігає `.npy` через `Sk.__jsfs`, але формат файлу — не бінарний NumPy-формат, а JSON-обгортка.
- **pandas** має власні in-memory сховища `__csvStore`/`__excelStore`. `to_csv()`/`to_excel()` ініціюють завантаження файла браузером, а не обов’язково пишуть у `epythonfs`. Для обміну даними з VFS краще використовувати `csv`/`open()` або Розпорядник файлів.

## Діалоги tkinter та easygui

Коли імпортується `tkinter`, модуль `lib/skulpt/_tkinter.js` з’єднує `engine.hooks.fs` із `fsToBrowse`:

- `fs.program_dir = '/'`, `fs.sep = '/'`;
- файли перелічуються з усієї VFS, починаючи з кореня;
- шляхи, які повертає діалог, є віртуальними шляхами типу `/data/a.txt`;
- `-initialdir` / `initialdir` задається відносно `program_dir` (зазвичай `''`, `data/`, `images/`);
- файли, вибрані користувачем у діалозі з комп’ютера, записуються у VFS через `hooks.apply_uploads`;
- скасування в Tk-функціях повертає порожній рядок `''`, а в `easygui` — `None`.

### `tkinter.filedialog`

Доступні `askopenfilename`, `askopenfilenames`, `asksaveasfilename`, `askdirectory` та пов’язані обгортки з `lib/skulpt/tkinter/filedialog.py`. Маски файлів підтримуються у вигляді `[('Текстові файли', '*.txt')]`.

### `easygui`

`easygui` — це чистий Python-модуль `lib/skulpt/easygui/easygui.py`, побудований поверх Tk-порту. Для роботи з VFS призначені:

| Функція | Що робить |
|---|---|
| `fileopenbox(default='*', filetypes=None, multiple=False)` | вибір файлу або списку файлів |
| `filesavebox(default='', filetypes=None)` | вибір імені для збереження |
| `diropenbox(default=None)` | вибір теки |

`default` може містити шлях і маску, наприклад `'/data/*.csv'` або `'/data/result.txt'`. Функції повертають віртуальний шлях або `None`, якщо діалог скасовано. `multiple=True` повертає список шляхів.

## Приклади

### Уведення та читання файла

```python
with open('/notes.txt', 'w') as f:
    f.write('Привіт з ЄPython!\n')
    f.write('Другий рядок.\n')

with open('/notes.txt', 'r') as f:
    print(f.read())
```

### Робота з теками

```python
import os

os.makedirs('/data', 0o777, True)  # третій аргумент — exist_ok

with open('/data/result.csv', 'w') as f:
    f.write('name;score\nАня;12\nМарко;10\n')

print(os.listdir('/data'))
print(os.path.exists('/data/result.csv'))

for folder, dirs, files in os.walk('/data'):
    print(folder, dirs, files)
```

### Вибір файла через easygui

```python
import easygui as eg

path = eg.fileopenbox(
    msg='Виберіть CSV-файл',
    title='Відкрити дані',
    default='/data/*.csv',
    filetypes=[('CSV-файли', '*.csv')],
)

if path is None:
    print('Діалог скасовано')
else:
    with open(path, 'r') as f:
        print(f.read())

out = eg.filesavebox(
    default='/data/result.txt',
    filetypes=[('Текстові файли', '*.txt')],
)
if out:
    with open(out, 'w') as f:
        f.write('Готово!')
```

### Вибір кількох файлів

```python
import easygui as eg

paths = eg.fileopenbox(
    default='/*.txt',
    filetypes=[('Текст', '*.txt')],
    multiple=True,
)

if paths:
    for p in paths:
        print('Обрано:', p)
```

### Діалог через tkinter

```python
from tkinter import Tk, filedialog

root = Tk()
root.withdraw()  # сховати головне вікно, лишити тільки діалог

path = filedialog.askopenfilename(
    title='Виберіть текстовий файл',
    initialdir='data',
    filetypes=[('Текстові файли', '*.txt')],
)

if path:
    with open(path, 'r') as f:
        print(f.read())
```

## Обмеження та усунення проблем

| Ситуація | Причина / що робити |
|---|---|
| Файли зникли після чистки браузера | VFS лежить у `localStorage`. Очищення даних сайту її видаляє. Зберігайте копії через **⬇️ Зберегти файл** або **💾 Зберегти проєкт**. |
| Файл видно в Розпоряднику, але немає у бічній панелі | Це різні списки. Для Python-коду використовуйте абсолютний шлях; для редагування додайте файл через **📤 Додати до проєкту**. |
| `open()` не знаходить файл | Перевірте точне ім’я, розширення та початковий `/`. Відносні шляхи залежать від `cwd` конкретного екземпляра VFS. |
| `os.chdir()` не впливає на `open()` | `os` і `open()` використовують різні екземпляри `FileSystem`. Надавайте перевагу абсолютним шляхам. |
| Діалог easygui/Tk починається не в потрібній теці | `initialdir` задається відносно кореня VFS (`''`, `data/`, `images/`). Перевірте, що така тека існує. |
| Не вдається завантажити файл із комп’ютера | Розпорядник приймає лише `.txt`, `.csv`, `.png`; бічна панель — `.py`, `.txt`, `.json`, `.csv`, `.png`. |
| Після видалення хочеться скасувати | Кошика немає. Видалення остаточне. Функція **«Відновлення файлу»** в головному меню стосується резервних копій коду редактора, а не файлів VFS. |
| `.yepp` відкрився без тек | Архів проєкту не зберігає структуру каталогів; відновлюйте теки вручну. |
| `shutil.make_archive()` падає | Функція не підтримується у браузерному середовищі. |
| `shutil.disk_usage()` показує нулі | Це імітація; реальний ліміт — квота `localStorage`. |
| `os.stat().st_mtime` дорівнює `0` | VFS не зберігає час створення/зміни. |
| Помилка через `~` у шляху | `os.path.expanduser()` не реалізований. Використовуйте `/...`. |
| Файл `/tmp/...` не видно в проєкті | Це нормально: тимчасові файли приховані від списку проєкту. |
| Після кнопки «Зупинити» зміни коду втрачено | Зупинка перезавантажує програму зі збереженої версії. Запустіть код повторно, щоб зберегти останні зміни. |
| Стартові приклади змінилися | Демонстраційні файли можуть перезаписуватися під час завантаження сторінки. Не використовуйте їх як єдину копію важливих даних. |
